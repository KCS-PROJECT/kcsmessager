# Research Plan: KCS Talk v4 사용성 검증
스킬: `design:user-research` (Image #6 적용 7/8) · 작성 2026-10-09 · 상태: **계획 (아직 참여자 조사 없음)**

## 1. 목표
1. 그룹사 임직원이 새 기능(대화 요약 · 음성메시지 · 연락처 보내기 · '통화' 폴더 · 대화 내보내기)을 **안내 없이 찾고 끝낼 수 있는가**.
2. 대화 요약이 실제 업무(회의 결정·요청 파악)에 쓸 만한가 — 추출형(Claude 미사용) 요약의 신뢰도.
3. 업무 우선 친구 탭(내 부서·일정 중 표시)과 조직도가 "누구에게 물어볼지" 찾는 시간을 줄이는가.

## 2. 방법
| 방법 | 대상 | 인원 | 기간 |
|---|---|---|---|
| 과업 기반 사용성 테스트 (원격 화면 공유, 생각 말하며 하기) | 케이씨에스·한네트·케이씨티 등 계열사 직원 | 6명 (부서 3 × 직급 2) | 1주 |
| 짧은 설문 (SUS 10문항 + 기능별 유용도 1~5) | 테스트 참여자 + 시범 사용자 | 30명+ | 1주 |
| 로그 지표 (선택, 동의 받은 시범 운영) | 시범 부서 | 1개 부서 | 2주 |

참여자 기준: 하루 메신저 사용 2시간 이상 3명 / 1시간 미만 3명, 40대 이상 2명 포함(글자 크기·대비 확인), 다른 계열사 사람과 대화가 잦은 사람 2명.

## 3. 과업 (성공 기준)
| # | 과업 | 성공 | 관찰 포인트 |
|---|---|---|---|
| T1 | "어제 프로젝트 팀 방에 40개가 쌓였습니다. 무엇이 결정됐는지 1분 안에 파악하세요." | 요약 칩 또는 메뉴 → 결정 사항 말하기 | 칩을 보는지, 요약을 믿는지(원문 확인 여부) |
| T2 | "김철수에게 박민수 연락처를 보내세요." | ＋ → 연락처 보내기 | ＋ 메뉴 발견 시간 |
| T3 | "회의 들어가기 전 15초짜리 음성메시지를 남기세요." | 녹음 → 보내기 | 녹음 자동 시작을 예상하는지, 마이크 권한 막힘 |
| T4 | "오늘 놓친 전화가 누구 것인지 확인하고 다시 거세요." | '통화' 폴더 → 방 열기 → 통화 | 부재중 표시 인지 |
| T5 | "프로젝트 방 대화를 보고서 첨부용 파일로 저장하세요." | ☰ → 대화 내보내기 | 메뉴 이름 기대값('저장', '백업'?) |
| T6 | 키보드만으로: "마지막 메시지에 👍 공감" | Alt+↑ → Shift+F10 → 공감 | 단축키 발견 가능성 (안내 필요?) |

측정: 성공률, 소요 시간, 오류 수, 과업 후 난이도(SEQ 1~7).

## 4. 인터뷰 가이드 (45분)
1. **Warm-up (5분)** — 하는 일, 하루에 메신저로 하는 일 세 가지.
2. **Context (10분)** — 최근 "단톡방 따라잡기"가 힘들었던 경험, 다른 계열사 사람 찾는 방법, 통화 vs 메시지 선택 기준.
3. **Deep dive (20분)** — T1~T6 수행 (생각 말하며).
4. **Reaction (5분)** — 요약 결과를 보여 주고 "이걸 보고 회의에 들어가겠습니까? 무엇이 빠졌습니까?"
5. **Wrap-up (5분)** — 가장 불편했던 한 가지, 없어도 되는 기능 한 가지.

탐색 질문: "그때 무엇을 찾고 있었나요?", "이 문구가 무슨 뜻이라고 생각했나요?", "평소라면 여기서 어떻게 하셨을까요?"
