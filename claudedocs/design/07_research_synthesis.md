# Research Synthesis: KCS Talk — 지금까지의 근거 정리
**Method:** 2차 자료 종합 (발주자 요청 이력 · 카카오 공식 발표 · 내부 디자인 점검 01~05) | **Participants:** 실제 사용자 0명 (발주자 1명의 요청 23건)
**Date:** 2026-10-08 ~ 2026-10-09 | 스킬: `design:research-synthesis` (Image #6 적용 8/8)

> 한계: 실제 임직원 조사 전이다. 아래 '테마'는 **가설**이며 `06_user_research_plan.md`의 테스트로 검증해야 한다.

### Executive Summary
발주자의 요청은 일관되게 **"카카오톡과 같은 익숙함 + 회사 업무에 맞춘 정보"** 로 모인다(카카오 기능 전부 / 회사 CI / 조직도 / 업무 우선 친구 탭). 반대로 업무와 무관한 기능(번역)은 분명히 거절했다. 내부 점검에서 가장 큰 위험은 **키보드·대비 같은 기본 접근성**과 **영어로 남은 확인 창**이었고 이번에 고쳤다. 다음 단계의 핵심은 "많이 쌓인 대화를 빨리 따라잡기"(요약)와 "누구에게 물을지 찾기"(조직도·친구)의 실제 효용 검증이다.

### Key Themes

#### Theme 1: 익숙함이 기본값 — "카카오톡처럼"
**Prevalence:** 요청 23건 중 9건이 '카카오톡 분석해서 넣어줘' 계열
**Supporting Evidence:**
- "카카오톡 상세히 분석해서 모든 대화기능 및 일정기능 모든기능을 찾아서 …" — 발주자
- "카카오톡 기능을 더 상세히 분석해서 더 개선하거나, 또는 추가할 사항 및 기능들을 만들어줘" — 발주자
**Implication:** 새 기능은 카카오톡 위치·이름을 따른다(＋ 메뉴의 음성메시지·연락처, ☰ 메뉴의 대화 내보내기, 채팅 탭 '통화' 폴더). 고유 기능을 넣을 때도 카카오톡 문법 안에서.

#### Theme 2: 회사 맥락이 화면 첫 줄에
**Prevalence:** 9건 (CI 로고 3, 조직도 3, 업무 우선 친구 탭·KCS 블루 고정 3)
**Supporting Evidence:**
- "조직 구성도를 첨부된 파일처럼 적용해줘" / "지주사 밑으로 한네트, 케이씨에스, 12개 계열사" — 발주자
- 비평 선택지에서 '업무 우선'·'KCS 블루만' 선택 — 발주자
**Implication:** 소셜 기능(펑·생일)은 기본 꺼짐, 내 부서·일정 중 표시가 먼저. 브랜드는 하나(KCS 네이비)로.

#### Theme 3: 필요 없는 기능은 짐 — "그럴 필요 없는데.."
**Prevalence:** 1건이지만 강한 신호 (번역 기능 전체 제거)
**Supporting Evidence:** "야 뭘하는데 번역이 필요한거야?" / "그럴필요없는데.." — 발주자
**Implication:** 기능 추가 전 '사내 업무에서 쓰는 장면'을 한 문장으로 말할 수 없으면 넣지 않는다. 이번 v4에서 AI 이미지 변환·오픈채팅 챗봇을 뺀 근거.

#### Theme 4: 기본기 결함이 신뢰를 깎는다 (내부 점검)
**Prevalence:** 점검 4건에서 반복 — 접근성 11, 문구 14, 토큰 6, 비평 9 항목
**Supporting Evidence:** 확인 창 'Yes/No' 영어, 메시지 메뉴 마우스 전용, 다크 모드 부재중 글자 3.45:1, 배율을 무시하는 글자 크기 — 01~04 문서
**Implication:** 기능 수보다 "어느 화면이든 깨지지 않고 읽힌다"가 먼저. 테스트로 회귀 방지(`AccessibilityTest`, `UxCopyTest`, `DesignSystemTest`).

### Insights → Opportunities
| Insight | Opportunity | Impact | Effort |
|---|---|---|---|
| 단톡방이 쌓이면 따라잡기 어렵다(카카오도 v26.6.0에서 요약 추가) | 요약 칩 + 결정/요청/질문 추출 → 회의 전 확인 | High | Med (완료, 검증 필요) |
| 사내에선 '누구에게 물을지'가 첫 질문 | 조직도 검색 결과에서 바로 연락처 보내기·통화 | High | Low |
| 통화를 놓치면 다시 찾기 어렵다 | '통화' 폴더 + 부재중 수 칩 | Med | Low (완료) |
| 키보드 위주 사용자(개발·사무) 존재 가능 | 단축키 안내를 더보기·도움말에 노출 | Med | Low |
| 관리·보고용 기록 요구 | 대화 내보내기(.txt) → 기간 선택·PDF는 요청 시 | Low | Med |

### User Segments Identified (가설)
| Segment | Characteristics | Needs | Size |
|---|---|---|---|
| 현장·영업 | 이동 중, 짧은 확인 | 음성메시지, 요약, 큰 글자 | ~30% |
| 사무·관리 | 단톡방 다수, 보고 | 요약, 내보내기, 공지·게시판 | ~45% |
| 개발·기술연구소 | 키보드 위주, 계열사 간 협업 | 단축키, 코드·링크, 조직도 검색 | ~25% |

### Recommendations
1. **요약 품질 검증 (High)** — 추출형 요약이 결정 사항을 놓치는 비율을 T1으로 측정. 낮으면 Claude 요약 사용 조건(키 설정) 안내를 더보기에 노출. 근거: Theme 1·Insight 1.
2. **단축키·접근성 안내 (Medium)** — Alt+↑/↓·Shift+F10·Ctrl+K 를 기능 둘러보기에 추가. 근거: Theme 4.
3. **조직도 → 행동 연결 (Medium)** — 조직도 사람 우클릭에 '연락처 보내기'. 근거: Theme 2.

### Questions for Further Research
- 요약을 원문 대신 믿고 행동하는가, 아니면 원문을 다시 읽는가?
- 음성메시지를 사내에서 쓰는 장면이 실제로 있는가(사무실 소음·예절)?
- 내보내기 파일을 어디에 쓰는가(보고서 첨부? 감사 대응?) — 형식 요구가 달라진다.

### Methodology Notes
발주자 1인의 요청을 '사용자 목소리'로 다뤘으므로 편향이 크다(의사결정자 ≠ 일반 직원). 카카오 기능 근거는 카카오 공식 발표(2·4·6차 정기 업데이트)만 사용. 내부 점검 수치는 오프스크린 렌더링·토큰 계산값이며 실제 스크린리더 검증은 하지 않았다.
